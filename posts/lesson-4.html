ملخص شامل ومنظم لدرس DDL CREATE

في هذا الدرس سنغوص في أعماق بناء قواعد البيانات، بدءاً من ضبط الترميز الصحيح، مروراً بهندسة الأعمدة والقيود، وصولاً إلى أوامر الإفراغ والهدم.

1

ضبط بيئة التخزين والترميز

قاعدة البيانات تمثل "مساحة التخزين الفعلية" (الدفتر)، والتطبيق يمثل "لغة النقل" (ساعي البريد). لضمان استيعاب كافة اللغات والحروف والرموز التعبيرية بدون مشاكل الترميز (???? أو تشوه النصوص):

  • utf8mb4 (Character Set): يدعم تخزين جميع لغات العالم مع الرموز التعبيرية (Emojis) بدقة تصل إلى 4 بايت لكل رمز.
  • utf8mb4_unicode_ci (Collation): يحدد قواعد الترتيب والمقارنة المعتمدة عالمياً مع تجاهل حساسية حالة الأحرف الكبيرة والصغيرة (Case-Insensitive).

-- إنشاء قاعدة البيانات مع تحديد الترميز وقواعد الترتيب صراحةً
CREATE DATABASE IF NOT EXISTS UniversityDB
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE UniversityDB;
2

الهيكلية المعيارية لبناء العمود

عند تعريف أي عمود داخل الجدول، يتبع محرك قواعد البيانات ترتيباً منطقياً محدداً. إليك هذا الجدول الذي يلخص القيود الهندسية:

القيد / الخاصية الدور الهندسي
NOT NULL يمنع ترك الحقل فارغاً، ويُستخدم للحقول الإلزامية في النظام.
DEFAULT يُسند قيمة تلقائية للحقل في حال لم يرسلها التطبيق أثناء الإضافة.
AUTO_INCREMENT يُولّد أرقاماً تسلسلية فريدة تلقائياً مع كل صف جديد.
UNIQUE يمنع تكرار القيمة في العمود عبر كامل الجدول (مثل البريد ورقم الهوية).
CHECK يتحقق منطقياً من مطابقة البيانات لشرط معين قبل قبولها.
PRIMARY KEY المعرّف الفريد للجدول (يجمع تلقائياً بين NOT NULL و UNIQUE).
FOREIGN KEY يضمن التكامل المرجعي بربط العمود بمفتاح أساسي في جدول آخر.
3

القيود: مستوى العمود مقابل الجدول

  • على مستوى العمود (Column-level): يُكتب بجانب اسم العمود مباشرة، ويُستخدم عندما يخص القيد عموداً واحداً فقط. (ملاحظة: NOT NULL و DEFAULT لا يُكتبان إلا هنا).
  • على مستوى الجدول (Table-level): يُكتب في نهاية الجدول، وتكمن أهميته في إمكانية تسمية القيد لتسهيل إدارته، وإنشاء المفاتيح المركبة.

-- أولاً: إنشاء الجدول الأب (Departments)
CREATE TABLE Departments (
    DeptID INT AUTO_INCREMENT PRIMARY KEY,
    DeptName VARCHAR(100) NOT NULL UNIQUE
);

-- ثانياً: إنشاء الجدول التابع (Employees) موضحاً المستويين
CREATE TABLE Employees (
    -- قيود على مستوى العمود (Column-level)
    EmployeeID INT AUTO_INCREMENT PRIMARY KEY,
    FullName VARCHAR(100) NOT NULL,
    Email VARCHAR(150) NOT NULL UNIQUE,
    AccountStatus VARCHAR(20) NOT NULL DEFAULT 'Active',
    Salary DECIMAL(10, 2) NOT NULL,
    DeptID INT,

    -- قيود على مستوى الجدول (Table-level)
    -- 1. قيد تحقق منطقي مسمى (Named Check Constraint)
    CONSTRAINT chk_minimum_salary CHECK (Salary >= 3000.00),

    -- 2. مفتاح أجنبي يربط الموظف بقسمه مع تحديد سلوك الحذف
    CONSTRAINT fk_employee_dept FOREIGN KEY (DeptID) 
        REFERENCES Departments(DeptID) 
        ON DELETE SET NULL
);

مثال المفتاح الأساسي المركب (Composite Primary Key):


-- جدول تسجيل المواد: لا يمكن للطالب تسجيل نفس المادة مرتين
CREATE TABLE CourseEnrollments (
    StudentID INT NOT NULL,
    CourseID INT NOT NULL,
    EnrollmentDate DATE DEFAULT (CURRENT_DATE),

    -- مفتاح أساسي مركب يتكون من عمودين معاً
    CONSTRAINT pk_student_course PRIMARY KEY (StudentID, CourseID)
);
4

أوامر الإفراغ والهدم

كلا الأمرين يندرجان تحت لغة تعريف البيانات (DDL)، ولكل منهما سلوك تشغيلي مختلف تماماً:

TRUNCATE TABLE

يُفرغ الجدول من جميع البيانات فوراً ويُعيد تصفير عداد AUTO_INCREMENT إلى (1)، مع الاحتفاظ بهيكل الجدول والأعمدة والقيود كاملة.

DROP TABLE

يمحو الجدول بالكامل من القرص الصلب (البيانات والهيكل والقيود معاً)، كأنه لم يكن موجوداً من الأساس.


-- إفراغ جدول التسجيل من السجلات مع بقاء الجدول جاهزاً للاستخدام
TRUNCATE TABLE CourseEnrollments;

-- حذف الجداول بالكامل وإزالتها من الوجود
DROP TABLE IF EXISTS CourseEnrollments;
DROP TABLE IF EXISTS Employees;
DROP TABLE IF EXISTS Departments;

-- حذف قاعدة البيانات بالكامل
DROP DATABASE IF EXISTS UniversityDB;

The Complete Guide to DDL CREATE in MySQL

mysql October 11, 2026 4 min read views

📚

A Complete, Structured Summary of DDL CREATE

In this lesson we dive deep into building databases: from configuring the correct encoding, through engineering columns and constraints, to the commands that empty and tear down tables.

1

Storage Environment & Character Encoding

A database represents the physical storage space, while your application acts as the transport medium. To guarantee support for all global alphabets, special characters, and emojis without data corruption (such as ???? or Mojibake), both layers must be explicitly configured:

  • utf8mb4 (Character Set): A 4-byte UTF-8 encoding standard that stores any character set worldwide, including modern symbols and emojis.
  • utf8mb4_unicode_ci (Collation): Defines comparison and sorting rules according to Unicode standards while remaining case-insensitive (ci).

-- Create the database explicitly defining character set and collation
CREATE DATABASE IF NOT EXISTS UniversityDB
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE UniversityDB;
2

Standard Column Definition Order & Constraints

When declaring columns inside a table, relational engines (such as MySQL/InnoDB) parse attributes in a strict, standard order:

Constraint / Property Architectural Role
NOT NULL Rejects NULL values; mandatory for business-critical attributes.
DEFAULT Assigns a fallback value when the insert statement omits the column.
AUTO_INCREMENT Generates an automatically incrementing integer sequence for new rows.
UNIQUE Ensures all values in the column remain distinct across the table.
CHECK Validates that inputs satisfy a specific boolean condition before storage.
PRIMARY KEY The unique row identifier; enforces both NOT NULL and UNIQUE implicitly.
FOREIGN KEY Enforces referential integrity by validating values against another table's primary key.
3

Column-Level vs. Table-Level Constraints

  • Column-Level: Declared inline immediately after the column's data type. Use this when the constraint evaluates a single column independently. Note: NOT NULL and DEFAULT can only be defined at this level.
  • Table-Level: Declared at the bottom of the table specification. Required for:
    • Assigning custom constraint names (CONSTRAINT constraint_name) for maintainability.
    • Defining Composite Keys that span across two or more columns.

Applied Implementation:


-- Parent Table: Departments
CREATE TABLE Departments (
    DeptID INT AUTO_INCREMENT PRIMARY KEY,
    DeptName VARCHAR(100) NOT NULL UNIQUE
);

-- Child Table: Employees (Demonstrating both levels)
CREATE TABLE Employees (
    -- Column-level constraints
    EmployeeID INT AUTO_INCREMENT PRIMARY KEY,
    FullName VARCHAR(100) NOT NULL,
    Email VARCHAR(150) NOT NULL UNIQUE,
    AccountStatus VARCHAR(20) NOT NULL DEFAULT 'Active',
    Salary DECIMAL(10, 2) NOT NULL,
    DeptID INT,

    -- Table-level constraints
    -- 1. Named business validation rule
    CONSTRAINT chk_minimum_salary CHECK (Salary >= 3000.00),

    -- 2. Foreign Key referencing the parent table with deletion handling
    CONSTRAINT fk_employee_dept FOREIGN KEY (DeptID) 
        REFERENCES Departments(DeptID) 
        ON DELETE SET NULL
);

Composite Primary Key Implementation:


-- Junction Table: Prevents duplicate registrations for the same student and course
CREATE TABLE CourseEnrollments (
    StudentID INT NOT NULL,
    CourseID INT NOT NULL,
    EnrollmentDate DATE DEFAULT (CURRENT_DATE),

    -- Table-level Composite Primary Key combining two columns
    CONSTRAINT pk_student_course PRIMARY KEY (StudentID, CourseID)
);
4

Deconstruction Commands: TRUNCATE vs. DROP

Both commands belong to the Data Definition Language (DDL) family, but they operate differently at the storage engine level:

TRUNCATE TABLE

Deletes all rows by deallocating table data pages rather than deleting row-by-row. It resets the AUTO_INCREMENT counter back to 1 while keeping the schema, columns, and constraints intact.

DROP TABLE

Permanently purges the table structure, its metadata, indexes, and all associated rows from disk.


-- Wipe all records while preserving table structure and resetting auto-increment
TRUNCATE TABLE CourseEnrollments;

-- Permanently remove tables from the database
DROP TABLE IF EXISTS CourseEnrollments;
DROP TABLE IF EXISTS Employees;
DROP TABLE IF EXISTS Departments;

-- Remove the entire database and all contained objects
DROP DATABASE IF EXISTS UniversityDB;
