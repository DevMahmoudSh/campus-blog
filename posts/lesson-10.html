حساب العمر في MySQL ودالة TIMESTAMPDIFF

الطريقة الدقيقة لحساب العمر هي استخدام دالة TIMESTAMPDIFF لأنها تقيس الفرق الفعلي بين تاريخين بناءً على التقويم الحقيقي (السنة، الشهر، اليوم، والسنوات الكبيسة).

⚠️

تجنب الطرح البسيط: طرح السنوات بالشكل YEAR(CURDATE()) - YEAR(date_of_birth) يعطي نتائج خاطئة إذا لم يأتِ يوم الميلاد بعد في السنة الحالية.

حساب العمر بالسنوات

SQL
SELECT TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()) AS age FROM table_name;

كيف تعمل الدالة داخلياً؟

تأخذ الدالة الصيغة TIMESTAMPDIFF(Unit, Date1, Date2) وتنفذ خطوتين:

  • تحسب الفرق المبدئي بين السنوات (سنة النهاية - سنة البداية).
  • تفحص (الشهر واليوم)؛ إذا لم يأتِ شهر ويوم الميلاد في السنة الحالية بعد، تطرح 1 تلقائياً من النتيجة.
2

حساب العمر بالسنوات والشهور واستخدام MOD

لعرض السنوات ومعها الشهور المتبقية، نحسب إجمالي الشهور ثم نأخذ باقي القسمة على 12 باستخدام % أو كلمة MOD:

السنوات والشهور المتبقية

SQL
SELECT TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()) AS years, TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()) % 12 AS months FROM table_name;

دمج النتيجة في نص واحد

SQL
SELECT CONCAT( TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()), ' سنة و ', TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()) % 12, ' شهر' ) AS full_age FROM table_name;

بدائل علامة %

يمكن استخدام MOD بدلاً من % بطريقتين تعطيان نفس النتيجة تماماً:

1. كمعامل:

SQL
TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()) MOD 12

2. كدالة قياسية (تعمل في أغلب قواعد البيانات):

SQL
MOD(TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()), 12)
3

تعامل TIMESTAMPDIFF مع التاريخ والوقت ومقارنة الوقت فقط

سلوك الدالة حسب نوع العمود

نوع البياناتسلوك TIMESTAMPDIFF
DATEتاريخ فقطتقبله الدالة بدون أخطاء لأن MySQL يجري تحويلاً تلقائياً في الخلفية ويضيف له وقت منتصف الليل 00:00:00.
DATETIME / TIMESTAMPتاريخ ووقتتقارن الدالة التاريخ والوقت معاً بدقة تصل إلى الثانية. فإذا وُلد شخص الساعة 10:00:00 صباحاً، لن تكتمل سنته الجديدة في يوم ميلاده عند الساعة 09:59:00 بل عند 10:00:00 تماماً.
TIMEوقت فقط بدون تاريخلا تقبله TIMESTAMPDIFF وتُرجع NULL.

البديل لمقارنة وقتين فقط بدون تاريخ

نستخدم دالة TIMEDIFF مع الانتباه إلى أن الوقت الأكبر (النهاية) يُكتب أولاً:

SQL
SELECT TIMEDIFF('14:30:00', '10:00:00') AS diff; -- النتيجة: 04:30:00

ولتحويل النتيجة إلى رقم (ثوانٍ أو دقائق) ندمجها مع TIME_TO_SEC:

SQL
SELECT TIME_TO_SEC(TIMEDIFF('14:30:00', '10:00:00')) / 60 AS diff_minutes; -- النتيجة: 270

العمود المحتسب (Generated Column)

هو عمود لا يُدخل المستخدم قيمته يدوياً، بل تُحسب تلقائياً بناءً على معادلة تعتمد على أعمدة أخرى في نفس الجدول باستخدام GENERATED ALWAYS AS.

مثال (حساب السعر الإجمالي تلقائياً)

SQL
CREATE TABLE orders ( id INT PRIMARY KEY AUTO_INCREMENT, price DECIMAL(10, 2), quantity INT, total_price DECIMAL(10, 2) GENERATED ALWAYS AS (price * quantity) STORED );

الفرق بين نوعي العمود المحتسب

وجه المقارنةVIRTUAL (الافتراضي)STORED
التخزين على القرصلا يأخذ مساحة تخزينية.يُخزّن فعلياً على القرص كأي عمود عادي.
وقت الحسابيُحسب لحظياً عند القراءة (SELECT).يُحسب عند الإدخال أو التعديل (INSERT / UPDATE).
الاستخدام الأنسبللمعادلات البسيطة وتوفير المساحة.للمعادلات الثقيلة أو عند الحاجة لقراءة سريعة جداً.

قيود ومزايا مهمة

🚫

قيد الحتمية (Deterministic): يجب أن تعطي المعادلة نفس النتيجة دائماً لنفس المدخلات. لذلك لا يمكن استخدام CURDATE() أو NOW() لحساب العمر داخل عمود محتسب؛ والحل البديل للدوال المتغيرة مع الزمن هو إنشاء View.

✅

المزايا: توحيد المنطق الحسابي في مكان واحد، تبسيط الاستعلامات، وإمكانية إضافة فهرس (INDEX) على العمود (سواء كان VIRTUAL أو STORED) لتسريع البحث والترتيب.

Calculating Age in MySQL With TIMESTAMPDIFF

The accurate way to calculate age is the TIMESTAMPDIFF function, because it measures the real difference between two dates based on the actual calendar (year, month, day, and leap years).

⚠️

Avoid simple subtraction: subtracting years as YEAR(CURDATE()) - YEAR(date_of_birth) gives wrong results when the birthday has not yet come this year.

Calculating Age in Years

SQL
SELECT TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()) AS age FROM table_name;

How Does the Function Work Internally?

The function takes the form TIMESTAMPDIFF(Unit, Date1, Date2) and performs two steps:

  • It calculates the initial difference between the years (end year - start year).
  • It checks the month and day; if the birthday's month and day have not yet arrived this year, it automatically subtracts 1 from the result.
2

Age in Years and Months Using MOD

To show the years together with the remaining months, we calculate the total number of months and then take the remainder of dividing by 12 using % or the keyword MOD:

Years and Remaining Months

SQL
SELECT TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()) AS years, TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()) % 12 AS months FROM table_name;

Combining the Result Into One Text

SQL
SELECT CONCAT( TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()), ' years and ', TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()) % 12, ' months' ) AS full_age FROM table_name;

Alternatives to the % Sign

MOD can replace % in two ways that give exactly the same result:

1. As an operator:

SQL
TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()) MOD 12

2. As a standard function (works in most databases):

SQL
MOD(TIMESTAMPDIFF(MONTH, date_of_birth, CURDATE()), 12)
3

How TIMESTAMPDIFF Handles Dates and Times, and Comparing Times Only

Behavior by Column Type

Data TypeTIMESTAMPDIFF Behavior
DATEDate onlyAccepted without errors, because MySQL converts it automatically in the background and adds a midnight time of 00:00:00.
DATETIME / TIMESTAMPDate and timeThe function compares the date and the time together, accurate to the second. If someone was born at 10:00:00 AM, their new year of age is not complete on their birthday at 09:59:00, but exactly at 10:00:00.
TIMETime only, no dateTIMESTAMPDIFF does not accept it and returns NULL.

The Alternative for Comparing Two Times Without a Date

We use the TIMEDIFF function, keeping in mind that the larger time (the end) is written first:

SQL
SELECT TIMEDIFF('14:30:00', '10:00:00') AS diff; -- Result: 04:30:00

To turn the result into a number (seconds or minutes), we combine it with TIME_TO_SEC:

SQL
SELECT TIME_TO_SEC(TIMEDIFF('14:30:00', '10:00:00')) / 60 AS diff_minutes; -- Result: 270

Generated Columns

A generated column is a column whose value the user does not enter manually. Instead, it is calculated automatically from a formula based on other columns in the same table, using GENERATED ALWAYS AS.

Example (Calculating the Total Price Automatically)

SQL
CREATE TABLE orders ( id INT PRIMARY KEY AUTO_INCREMENT, price DECIMAL(10, 2), quantity INT, total_price DECIMAL(10, 2) GENERATED ALWAYS AS (price * quantity) STORED );

The Difference Between the Two Types of Generated Columns

ComparisonVIRTUAL (default)STORED
Disk storageTakes no storage space.Physically stored on disk like any normal column.
When it is calculatedCalculated on the fly when read (SELECT).Calculated on insert or update (INSERT / UPDATE).
Best used forSimple formulas and saving space.Heavy formulas, or when very fast reads are needed.

Important Restrictions and Benefits

🚫

The deterministic rule: the formula must always give the same result for the same inputs. That is why CURDATE() or NOW() cannot be used to calculate age inside a generated column; the alternative for time-dependent functions is to create a View.

✅

Benefits: the calculation logic lives in one place, queries become simpler, and you can add an INDEX on the column (whether VIRTUAL or STORED) to speed up searching and sorting.
