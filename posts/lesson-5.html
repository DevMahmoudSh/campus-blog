العلاقات بين الجداول والمفاتيح الأجنبية في MySQL

ملخص تطبيقي يشرح تقسيم الجداول (Normalization)، وأنواع العلاقات، والمفتاح الأجنبي، وسلوك الحذف والتعديل، مع الأكواد العملية.

حمّل ملخص المحاضرة

ملف PDF منسّق وجاهز للمراجعة والطباعة دون اتصال بالإنترنت

1

أولاً: ملخص العلاقات وتقسيم الجداول (Normalization)

الهدف الأساسي من تصميم قواعد البيانات هو ترتيب البيانات وتقليل التكرار المزعج. إليكم كيف نطبق أنواع العلاقات:

علاقة واحد لواحد (One-to-One)

لتجنب تكرار البيانات، نقوم بتقسيم الجدول الكبير إلى جدولين. على سبيل المثال، تم تقسيم جدول الموظفين إلى جدول للبيانات الشخصية (Employees_Table) وجدول للرواتب (Salaries_Table). وكذلك بالنسبة للطلاب، تم فصل البيانات الشخصية (Students_Table) عن التفاصيل الأكاديمية (Acad_students).

علاقة واحد لمتعدد (One-to-Many)

تظهر هذه العلاقة بوضوح بين فصائل الدم (Blood_Types_Table) والمرضى (Patients_Table). الفكرة هنا أن فصيلة الدم الواحدة (مثل O+) يمكن أن يحملها أكثر من مريض، لكن المريض الواحد لا يمتلك سوى فصيلة دم واحدة.

علاقة متعدد لمتعدد (Many-to-Many)

مثل العلاقة بين المرضى (Patients_Table) والأمراض (Diseases_Table). المريض قد يُصاب بعدة أمراض، والمرض الواحد قد يُصيب عدة مرضى. لأن قاعدة البيانات لا تستوعب هذه العلاقة مباشرة، نقوم بحلها برمجياً بإنشاء "جدول وسيط" (Patient_Diseases_Table) يكسر هذه العلاقة الكبيرة ويحولها إلى علاقتي "واحد لمتعدد".

2

ثانياً: ما هو المفتاح الأجنبي (Foreign Key)؟

ببساطة، هو حقل نضعه في جدول (نسميه الجدول الابن) ليكون بمثابة "جسر" يربطنا بالمفتاح الأساسي (Primary Key) في جدول آخر (نسميه الجدول الأب).

🎯

وظيفته الأساسية: الحفاظ على ما يُسمى بـ "التكامل المرجعي"، أي أنه يمنع إدخال بيانات عشوائية ويضمن ألا يحتوي الجدول الابن على سجلات "يتيمة" ليس لها أصل في الجدول الأب.

3

ثالثاً: ماذا يحدث عند الحذف أو التعديل؟ (ON DELETE & ON UPDATE)

هذه الخصائص تخبر قاعدة البيانات بما يجب فعله في الجدول الابن إذا تم حذف أو تعديل بيانات الجدول الأب:

الخيار السلوك
CASCADE المتتبع المتسلسل إذا قمت بحذف أو تعديل السجل الأب، سيتم تلقائياً حذف أو تعديل السجلات المرتبطة به في الجدول الابن.
RESTRICT المانع الصارم يمنعك تماماً من حذف أو تعديل السجل الأب طالما توجد سجلات مرتبطة به في الجدول الابن (لحماية البيانات من الضياع).
SET NULL التفريغ إذا قمت بحذف أو تعديل السجل الأب، ستبقى بيانات الابن موجودة، ولكن قيمة حقل المفتاح الأجنبي ستصبح فارغة (NULL).
4

رابعاً: أكواد MySQL (التطبيق العملي)

1. علاقة واحد لواحد (1:1)

لضمان أن الموظف له راتب واحد فقط، نضيف قيد UNIQUE بجانب المفتاح الأجنبي: 


CREATE TABLE Salaries_Table (
    Sala_Id INT PRIMARY KEY,
    hours_no INT,
    hours_rate INT
);

CREATE TABLE Employees_Table (
    Emp_Id INT PRIMARY KEY,
    Name VARCHAR(100),
    Salar_id INT UNIQUE, -- هذا القيد يضمن أن العلاقة 1:1
    FOREIGN KEY (Salar_id) REFERENCES Salaries_Table(Sala_Id)
    ON DELETE SET NULL
    ON UPDATE CASCADE
);

2. علاقة واحد لمتعدد (1:M)

المريض له فصيلة دم واحدة، وفصيلة الدم لها عدة مرضى: 


CREATE TABLE Blood_Types_Table (
    Blood_ID INT PRIMARY KEY,
    Blood_type VARCHAR(10) NOT NULL
);

CREATE TABLE Patients_Table (
    Patient_ID INT PRIMARY KEY,
    Name VARCHAR(100),
    Blood_Id INT,
    FOREIGN KEY (Blood_Id) REFERENCES Blood_Types_Table(Blood_ID)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);

3. علاقة متعدد لمتعدد (M:M)

هنا نقوم بإنشاء الجدول الوسيط الذي يحتوي على مفتاحين أجنبيين: 


CREATE TABLE Diseases_Table (
    Diseases_ID VARCHAR(10) PRIMARY KEY,
    Disease_name VARCHAR(100)
);

CREATE TABLE Patient_Diseases_Table (
    Patient_Id INT,
    Diseases_Id VARCHAR(10),
    Diagnosis_Date YEAR,

    -- دمج المفتاحين كـ مفتاح أساسي مركب للجدول الوسيط
    PRIMARY KEY (Patient_Id, Diseases_Id),

    -- الربط مع جدول المرضى
    FOREIGN KEY (Patient_Id) REFERENCES Patients_Table(Patient_ID)
    ON DELETE CASCADE
    ON UPDATE CASCADE,

    -- الربط مع جدول الأمراض
    FOREIGN KEY (Diseases_Id) REFERENCES Diseases_Table(Diseases_ID)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);
5

خامساً: استخدام ALTER TABLE للتعديل على الجداول

إذا نسيت إضافة المفتاح الأجنبي عند إنشاء الجدول، لا تقلق! يمكنك إضافته لاحقاً، أو حتى حذفه باستخدام هذه الأوامر:

1. حذف المفتاح الأجنبي (باستخدام اسم القيد مباشرة)


ALTER TABLE Patients_Table
DROP CONSTRAINT fk_blood_patient;

2. إضافة مفتاح أجنبي (بدون إعطائه اسماً يدوياً)

سيقوم النظام بتوليد اسم تلقائي له. 


ALTER TABLE Patients_Table
ADD FOREIGN KEY (Blood_Id) REFERENCES Blood_Types_Table(Blood_ID)
ON DELETE SET NULL
ON UPDATE CASCADE;

3. إضافة مفتاح أجنبي (مع تحديد اسم واضح له)


ALTER TABLE Patients_Table
ADD CONSTRAINT fk_blood_patient
FOREIGN KEY (Blood_Id) REFERENCES Blood_Types_Table(Blood_ID)
ON DELETE SET NULL
ON UPDATE CASCADE;
💡

نصيحة: من الأفضل دائماً تسمية القيود ليسهل إدارتها لاحقاً.

A Practical Guide to Database Normalization and Relationships in MySQL

Database Normalization and Relationships Summary

Database design concepts that reduce redundancy and define how tables relate to each other, from relationship types to foreign keys and their MySQL code.

1

Types of Table Relationships

The provided documents summarize database design concepts to reduce redundancy and define table relationships:

One-to-One (1:1)

Illustrated by splitting the original employees table into two separate tables: Employees_Table and Salaries_Table. It also shows dividing the students table into personal data (Students_Table) and academic data (Acad_students).

One-to-Many (1:M)

Shown in the relationship between blood types (Blood_Types_Table) and patients (Patients_Table), where multiple patients can share one blood type.

Many-to-Many (M:M)

Displayed between patients (Patients_Table) and diseases (Diseases_Table). This is resolved programmatically by creating a junction table (Patient_Diseases_Table) that breaks the many-to-many relationship into two one-to-many relationships.

2

Foreign Key Definition

A Foreign Key is a field (or collection of fields) in one table that uniquely identifies a row of another table (usually pointing to a Primary Key).

🎯

Main purpose: to maintain referential integrity, ensuring that the relationship between tables remains valid and preventing orphaned records.

3

ON DELETE and ON UPDATE

These properties define the automatic action taken on the "child" table when the referenced record in the "parent" table is deleted or updated:

Action Behavior
CASCADE Automatically deletes or updates the matching records in the child table when the parent record is deleted or updated.
RESTRICT / NO ACTION Prevents the deletion or update of the parent record if there are matching records in the child table.
SET NULL Sets the foreign key column values in the child table to NULL when the parent record is deleted or updated.
4

MySQL Codes

1. One-to-One Relationship (1:1)

To ensure a strictly 1:1 relationship, a UNIQUE constraint is added to the foreign key: 


CREATE TABLE Salaries_Table (
    Sala_Id INT PRIMARY KEY,
    hours_no INT,
    hours_rate INT
);

CREATE TABLE Employees_Table (
    Emp_Id INT PRIMARY KEY,
    Name VARCHAR(100),
    Salar_id INT UNIQUE, 
    FOREIGN KEY (Salar_id) REFERENCES Salaries_Table(Sala_Id)
    ON DELETE SET NULL
    ON UPDATE CASCADE
);

2. One-to-Many Relationship (1:M)


CREATE TABLE Blood_Types_Table (
    Blood_ID INT PRIMARY KEY,
    Blood_type VARCHAR(10) NOT NULL
);

CREATE TABLE Patients_Table (
    Patient_ID INT PRIMARY KEY,
    Name VARCHAR(100),
    Blood_Id INT,
    FOREIGN KEY (Blood_Id) REFERENCES Blood_Types_Table(Blood_ID)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);

3. Many-to-Many Relationship (M:M)


CREATE TABLE Diseases_Table (
    Diseases_ID VARCHAR(10) PRIMARY KEY,
    Disease_name VARCHAR(100)
);

CREATE TABLE Patient_Diseases_Table (
    Patient_Id INT,
    Diseases_Id VARCHAR(10),
    Diagnosis_Date YEAR,
    
    PRIMARY KEY (Patient_Id, Diseases_Id),
    
    FOREIGN KEY (Patient_Id) REFERENCES Patients_Table(Patient_ID)
    ON DELETE CASCADE
    ON UPDATE CASCADE,
    
    FOREIGN KEY (Diseases_Id) REFERENCES Diseases_Table(Diseases_ID)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);
5

Using ALTER TABLE

1. Dropping a Foreign Key (without using the word "FOREIGN KEY")

You can drop the constraint directly using its name with the DROP CONSTRAINT command. 


ALTER TABLE Patients_Table
DROP CONSTRAINT fk_blood_patient;

2. Adding a Foreign Key WITHOUT a name

If you do not specify a name, MySQL will automatically generate a default constraint name. 


ALTER TABLE Patients_Table
ADD FOREIGN KEY (Blood_Id) REFERENCES Blood_Types_Table(Blood_ID)
ON DELETE SET NULL
ON UPDATE CASCADE;

3. Adding a Foreign Key WITH a name

You can specify a custom name by using the CONSTRAINT keyword followed by your chosen name before defining the foreign key. 


ALTER TABLE Patients_Table
ADD CONSTRAINT fk_blood_patient 
FOREIGN KEY (Blood_Id) REFERENCES Blood_Types_Table(Blood_ID)
ON DELETE SET NULL
ON UPDATE CASCADE;
